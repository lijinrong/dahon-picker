# 大行(Dahon)折叠车选购器 · v1 设计文档

日期:2026-09-14
状态:待用户审阅

## 1. 背景与问题

大行折叠车在国内在售型号众多,命名体系混杂:官方代码(如 KAA084)与市场俗称(K3、P8、D8)并存,普通消费者很难判断"哪款适合我"。本产品用一个轻量网页工具回答这个问题:**"我想买车,预算 X,用来 Y,该买哪款大行?"**

## 2. 定位与受众

- **受众**:准备购买大行折叠车的普通消费者(新手为主),以及帮朋友参谋的人
- **定位**:个人项目 + 作品;**预留商业化可能**——v1 不接导购链接,但数据结构和页面预留位置(`affiliateUrl` 字段、"价格仅供参考"合规标注)
- **传播预期**:通过链接/二维码在骑行群、社交平台分享(结果页 URL 可直接转发)

## 3. 目标与非目标

### v1 目标

1. 4 个问题的选购向导,30 秒内完成,输出 2-4 款推荐 + 人话理由
2. 型号百科:全部收录车型的参数、筛选、多款对比
3. 型号命名解读器:官方代码逐位解码 + 俗称双向查询
4. 静态数据驱动,zod 校验,数据更新无需碰服务器
5. 移动优先体验,关键页性能达标(LCP < 2.5s)

### v1 非目标(明确不做)

- 后端服务、数据库、账号系统
- 爬虫/自动数据同步
- 微信小程序版
- 真实导购/分销链接
- 实拍图片
- 收录停产/二手经典老款(数据结构预留口子,v2 扩展)

## 4. 产品设计

### 4.1 信息架构(6 个页面)

| 路由 | 内容 | 渲染方式 |
|---|---|---|
| `/` | 首页:价值主张 + "开始选购"入口 + 解读器次入口 | 静态 + Wizard 岛屿 |
| `/result` | 向导结果:推荐 2-4 款 + 理由 | 岛屿(URL 参数承载答案,可分享) |
| `/bikes` | 型号百科:列表 + 筛选(轮径/价格/用途/变速) | 静态 + BikeTable 岛屿 |
| `/bikes/[slug]` | 型号详情:参数、命名解读、优缺点、参考价 | **纯静态 SSG,SEO 主力页** |
| `/compare` | 对比页:任选 2-3 款横向对比 | 岛屿 |
| `/decode` | 命名解读器 + 命名体系长文 | 岛屿 + 静态长文 |

### 4.2 选购向导(4 题,一屏一题,点选式)

| # | 问题 | 选项(枚举值) |
|---|---|---|
| 1 | 预算 | `<2000` / `2000-4000` / `4000-8000` / `>8000` |
| 2 | 主要用途 | `commute` 城市通勤 / `sport` 运动健身 / `travel` 旅行携车 / `casual` 休闲代步 |
| 3 | 折叠频率 | `daily` 每天都要折 / `occasional` 偶尔折 / `rarely` 基本不折 |
| 4 | 身高 | `<160` / `160-170` / `170-180` / `>180` cm |

刻意不问"路况/变速偏好"——普通消费者答不上来,坡道适配从用途推断(sport → 需要更大变速范围)。

向导答案编码进 `/result` 的 URL 查询参数(具体编码实现时定,要求:短、可读、可直接粘贴分享),对方打开即见同一份推荐。

### 4.3 推荐引擎(纯规则、可解释)

实现为纯函数 `recommend(answers, bikes) → RankedBike[]`,无外部依赖:

1. **硬过滤**(淘汰):
   - 在售(`status === "active"`)
   - 身高落在车型适配区间内
   - 价格 ≤ 预算上限 × 1.1(允许小幅上浮)
2. **软打分**(加权求和,权重在实现期用测试调优,维度如下):
   - 用途标签匹配度(主权重)
   - 折叠便携(`carryScore`),权重随 `foldFrequency` 变化:daily 高权重、rarely 低权重
   - 爬坡能力(`climbScore`),仅 `sport`/通勤有坡场景计分
   - 重量(与 `travel` 用途强相关)
3. **输出**:得分排序取前 2-4 款,每款附由命中维度生成的理由文案("因为你每天要带车上地铁,这款折叠后最紧凑")
4. **兜底**:硬过滤后为空 → 放宽为"最接近"模式,明示差距("预算差 300,其余都合适")

设计原则:**领域知识沉淀在数据,规则引擎只做比较**。调优推荐质量 = 改数据/权重,不改架构。

### 4.4 命名解读器

- **`/decode` 岛屿**:输入任意官方代码(如 `KAA084`)→ 逐位拆解、高亮每位含义(类 VIN 解码器体验)
- **双向查询**:官方代码 ↔ 市场俗称(K3/P8/D8)互查;模糊输入给相似建议("没找到 KKA084,你想找的是 KAA084?")
- **详情页自动解读**:每款车详情页自动渲染本车型解读标签
- **规则表驱动**(DRY):`naming.json` 结构化编码命名规则,`decodeModel(code, rules)` 纯函数生成解读;不按规则的车型用数据字段显式覆盖
- **准确性 = 生命线**:规则数据交叉验证(官网 + 多渠道);没把握的位次标注"官方未公开/存在地区差异",不臆造

### 4.5 型号百科与对比

- 百科筛选维度:轮径、价格区间、用途、变速数、(预留)在售状态
- 对比页:URL 参数携带车型 ids,最多 3 款,突出差异行(不同值高亮)

## 5. 数据设计

### 5.1 `src/data/bikes.json`(每款车型一条)

```jsonc
{
  "slug": "kaa084",                     // 唯一,URL 用
  "model": "KAA084",                    // 官方代码
  "marketingName": "K3 Plus",           // 市场俗称
  "series": "K",
  "status": "active",                   // active | discontinued(停产口子)
  "discontinuedInfo": null,             // 预留:{ lastPriceCny, year }
  "wheelSize": 16,                      // 轮径英寸
  "weightKg": 9.5,
  "folding": { "mechanism": "磁吸快折", "foldedSize": "…", "carryScore": 5 },  // carryScore 1-5 携带便利评级
  "drivetrain": { "speeds": 9, "climbScore": 3 },                            // climbScore 1-5 爬坡评级
  "priceCny": 3998,                     // 参考价
  "priceUpdatedAt": "2026-09-14",
  "heightRangeCm": [155, 185],
  "useCases": ["commute", "travel"],    // commute/sport/travel/casual
  "highlights": ["…"],
  "pros": ["…"], "cons": ["…"],
  "nameDecodeOverride": null,           // 规则例外时手工覆盖解读
  "specs": { "车架": "…", "变速": "…", "刹车": "…" },  // 开放键值对,详情页展示
  "affiliateUrl": null,                 // 商业化预留,null 不展示
  "sources": ["大行官网", "京东自营"],
  "updatedAt": "2026-09-14"
}
```

### 5.2 `src/data/naming.json`

```jsonc
{
  "positions": [
    { "index": 0, "dimension": "系列/轮径", "map": { "K": "…", "P": "…" } },
    { "index": 1, "dimension": "…", "map": { "A": "…" } }
    // 具体规则由数据收集阶段考证后填充
  ],
  "nicknames": { "K3": "kaa084", "P8": "paa083" },
  "uncertain": [ { "note": "第 3 位官方未公开统一规则" } ]
}
```

### 5.3 数据收集与维护

- **收集**:开发初期通过网络检索(大行官网、京东/天猫旗舰店、评测文章)整理;`carryScore`/`climbScore` 为整理时的人工评级(参考齿比、重量、折叠尺寸综合给出)
- **校验**:build 时 zod 全量校验——slug 唯一、枚举合法、价格区间合理、身高区间有序、价格/更新日期字段成对出现;任何一条坏数据 fail build
- **维护**:新车型发布时手动更新 JSON → push → CI 自动校验构建上线
- **目标规模**:国内在售主流型号全部收录(预计 30-60 款,以实际考证为准)

### 5.4 图片策略(v1)

不放实拍图(版权风险)。用系列色块 + 轮径尺寸示意图代替,详情页以参数和文字解读为主。授权图到位后(v2)再加图片字段。

## 6. 技术架构

### 6.1 选型

- **Astro(静态生成)+ Vue 岛屿**:详情页/长文纯静态(SSG,SEO 就绪、首屏快);向导/筛选/对比/解读器四个交互岛屿按需水合
- **TypeScript** 全覆盖,`lib/` 纯函数无 DOM 依赖
- **Vitest** 单测 + **Playwright** E2E
- 遵循全局 web 规范:design tokens(CSS 自定义属性)、语义 HTML、动效仅 compositor 友好属性

### 6.2 目录结构

```
dahon-picker/
├── src/
│   ├── data/
│   │   ├── bikes.json            # 车型数据(唯一数据源,手动维护)
│   │   └── naming.json           # 命名规则表
│   ├── lib/
│   │   ├── schema.ts             # zod schema + 类型推导
│   │   ├── recommend.ts          # 推荐引擎(纯函数)
│   │   ├── reasons.ts            # 推荐理由文案生成(纯函数)
│   │   ├── filter.ts             # 百科筛选(纯函数)
│   │   ├── decode.ts             # 命名解读(纯函数)
│   │   └── urlState.ts           # 向导答案 ↔ URL 参数编解码(纯函数)
│   ├── components/               # Vue 岛屿
│   │   ├── Wizard.vue            # 向导 + 结果渲染(共一个岛)
│   │   ├── BikeTable.vue         # 百科列表 + 筛选
│   │   ├── CompareTable.vue      # 对比表
│   │   └── Decoder.vue           # 命名解读器
│   ├── pages/                    # Astro 页面(SSG 生成全部详情页)

│   └── styles/                   # tokens.css 等,移动优先

    ├── unit/                     # vitest

    └── e2e/                      # Playwright
```

### 6.3 岛屿边界

Wizard(含结果)自成一个岛,答题状态不出岛;BikeTable、CompareTable、Decoder 各自成岛。四岛互不依赖,页面其余部分纯静态零 JS。

### 6.4 视觉方向

编辑杂志感、数据为主角;层级靠字号对比与留白,避免"参数表格堆砌"的工具脸。实现阶段用 frontend-design 技能具体化,遵循全局 design-quality 规范(反模板化)。

## 7. 错误处理

| 场景 | 行为 |
|---|---|
| 硬过滤后无匹配 | 放宽为"最接近"模式,明示差距维度 |
| `/result` 参数缺失/非法 | 校验失败带回首页向导,不留报错页 |
| `/decode` 未知输入 | 模糊匹配给相似建议;找不到明说"未收录",不猜 |
| 数据本身有错 | zod build 时拦截,fail the build |
| 浏览器禁用 JS | 静态内容照常;向导/解读器显示降级提示 |
| 价格时效 | 每款车标注"参考价 · 更新于 YYYY-MM";页脚免责声明"价格仅供参考,以实际渠道为准" |

## 8. 测试策略(TDD,覆盖率 ≥ 80%)

- **单元(vitest,主战场)**:`recommend / reasons / filter / decode / urlState / schema` 全部先测后写;重点用例:空结果兜底、预算边界(+10% 容差)、身高临界值、模糊匹配、命名规则例外、URL 编解码往返
- **数据测试**:全部车型过 schema;slug 唯一;decode 规则表能解释全部在售代码(例外必须显式标注);nickname 映射指向存在的 slug
- **E2E(Playwright,移动视口)**:向导→结果→详情主线;解读器查询;百科筛选;对比页
- **视觉回归**:320 / 375 / 768 三档关键页截图
- **可访问性**:向导键盘可操作、焦点管理、对比度检查

## 9. 部署与维护

- **仓库**:`~/projects/dahon-picker`,git 管理
- **托管**:Cloudflare Pages(免费,push 自动构建发布;传播需要时再绑自定义域名)
- **更新流程**:改 `bikes.json` → 本地 `npm run validate` → commit/push → CI(校验+测试+构建)→ 自动上线
- **CI**:GitHub Actions 或 Cloudflare Pages 内置流程(实现时定),必须包含数据校验与测试

## 10. 成功标准

1. 4 题 30 秒内可完成,推荐结果每款都有可解释理由
2. 收录国内在售主流型号(≥30 款,以实际考证为准),数据 100% 过校验
3. 关键页 LCP < 2.5s、CLS < 0.1(移动端)
4. 结果页 URL 分享后打开即还原同一推荐
5. 解读器能解释全部收录车型的官方代码,无臆造内容
